# 몬스터웨이브 에셋 목록

지금 게임의 그래픽과 소리는 대부분 코드로 만든 프로토타입이다(실제 그림이 들어간 것은 표에 "완료"로 적는다). 이 문서는 실제 에셋으로 바꿀 때 필요한 목록과 규격이다.

- **그림체: HD (일반 그림)**. 모든 이미지는 **게임 화면 표시 크기의 2배**로 제작한다.
  게임 해상도는 960×640이지만 태블릿이나 큰 화면에서 1.2~1.5배로 늘어나므로, 2배로 만들어야 흐려지지 않는다.
- 아래 표의 "표시 크기"는 지금 프로토타입이 960×640 화면에서 차지하는 크기, "제작 크기"가 실제로 만들 크기다.
- 모든 이름, 캐릭터, 그래픽, 소리는 오리지널이어야 한다. 무료 에셋을 쓸 때는 라이선스(예: CC0)를 확인한다.

## 1. 공통 규격

### 이미지
| 항목 | 규격 |
| --- | --- |
| 확장자 | `.png` (투명 배경, 32비트). 용량을 더 줄이려면 `.webp`도 가능 |
| 묶음 | **텍스처 아틀라스**: 한 장 이미지 + `.json` (TexturePacker의 Phaser 형식) |
| 아틀라스 크기 | 한 장 최대 **2048×2048** (휴대폰 호환). 넘으면 여러 장으로 나눈다 |
| 기준점 | 캐릭터·설치물·벽은 **발밑(아래 가운데)**. 게임이 발밑 기준으로 위치와 앞뒤 순서를 정한다 |
| 프레임 | 한 시트 안에서는 칸 크기를 통일하고, 발 위치를 같은 높이에 맞춘다. 칸 사이 여백 2px |
| 방향 | 3/4 시점, **5방향(아래, 오른쪽 아래, 오른쪽, 오른쪽 위, 위)**만 그리고 왼쪽 3방향은 좌우 반전 |
| 색 입히기 | "흰색으로 그려 두면 코드로 색을 입힐 수 있음"이라고 적힌 것은 흰색/회색조로 제작 |
| 피격 깜빡임 | 맞았을 때 흰색 번쩍임은 코드로 처리하므로 따로 그리지 않는다 |

### 소리
| 항목 | 효과음 | BGM |
| --- | --- | --- |
| 확장자 | `.ogg` + `.mp3` (둘 다) | `.ogg` + `.m4a` (둘 다) |
| 형식 | 44.1kHz, 모노, 96~128kbps | 44.1kHz, 스테레오, 128~192kbps |
| 비고 | 최고 음량 -1dBFS, 소리끼리 체감 음량을 맞춘다 | **끊김 없이 반복(루프)** 되게 |
| 원본 | `.wav`(44.1kHz/16bit)는 따로 보관 | 같음 |

효과음은 하나의 파일에 이어 붙인 **오디오 스프라이트**(`.ogg`/`.mp3` + `.json`)로 만들면 불러오기가 빠르다.

### 용량
웹 게임이므로 처음 받는 용량은 **10MB 안쪽**을 목표로 한다. BGM이 가장 크므로, 게임 중 곡은 타이틀 이후에 나중에 불러온다.

## 3. 캐릭터 (애니메이션 시트)

각 캐릭터는 5방향 × 동작별 프레임.

| | 캐릭터 | 표시 크기 | 한 칸 크기 | 필요한 동작 (프레임 수) |
| --- | --- | --- | --- | --- |
| [ ] | 플레이어 | 24×48 | 64×96 | 서 있기 1 (완료), 걷기 1~2 (1장씩 완료, 옆 방향 반대 발 남음), 맞음 1 |
| [ ] | 플레이어 무기 (손에 든 모습) | 18×6 | 48×24 | 무기 7종, 오른쪽을 향하게 (조준 방향으로 회전) |
| [ ] | 그런트 | 26×41 | 64×96 | 서 있기 1, 걷기 1~2, 공격 4, 맞음 1 |
| [ ] | 러너 | 18×27 | 48×64 | 서 있기 1, 달리기 1~2, 공격 3, 맞음 1 |
| [ ] | 브루트 | 40×63 | 96×128 | 서 있기 1, 걷기 1~2, 공격 4, 맞음 1 |
| [ ] | 임프 | 24×45 | 64×96 | 서 있기 1, 걷기 1~2, 주문 4, 맞음 1 |
| [ ] | 발밑 그림자 | 가변 | 64×32 | 부드러운 타원 1장 (크기는 코드에서 조절) |

표의 프레임 수는 **한 방향 기준**이다. 모든 동작을 5방향으로 그린다(왼쪽 3방향은 좌우 반전).

**서 있기**는 움직이지 않는 1장이다. 몬스터도 걷기 사이에 끼우는 기본자세로 필요하다.

**걷기(러너는 달리기)**는 발 뻗기 그림을 반복한다. 방향에 따라 장 수와 순서가 다르다.

| 방향 | 걷기 그림 | 재생 순서 |
| --- | --- | --- |
| 아래, 위 | 1장 (발 뻗기) | 뻗기 → 뻗기(좌우 반전) → 반복 (서기 없음) |
| 오른쪽 아래, 오른쪽, 오른쪽 위 | 2장 (왼발 앞, 오른발 앞) | 서기 → 왼발 → 서기 → 오른발 |

- 아래·위는 좌우가 대칭이라 반전하면 반대 발을 뻗은 모습이 된다. 옆을 보는 3방향은 반전하면 왼쪽을 보게 되므로 2장을 그린다.
- 걸음마다 몸을 살짝 들썩이는 건 코드로 처리한다.
- 그래서 걷기는 한 캐릭터당 5방향 합계 **8장**이다.

| 캐릭터 | 서 있기 | 걷기 | 공격·주문 | 맞음 | 5방향 합계 |
| --- | --- | --- | --- | --- | --- |
| 플레이어 | 5 (완료) | 8 (5장 완료) | — | 5 | 18 |
| 그런트 | 5 | 8 | 20 | 5 | 38 |
| 러너 | 5 | 8 | 15 | 5 | 33 |
| 브루트 | 5 | 8 | 20 | 5 | 38 |
| 임프 | 5 | 8 | 20 | 5 | 38 |

**죽음 동작은 그리지 않는다.** 죽으면 캐릭터 그림이 바로 사라지고, 그 자리에서 사망 파편과 체액 튐(6장 이펙트)이 터진다. 파편 색은 `src/config/monsters.ts`의 `color`(플레이어는 `src/config/player.ts`)로 입힌다.

### 플레이어 방향
- 몸은 **이동 방향이 아니라 총구(조준) 방향**을 본다. 마우스를 왼쪽 위에 두면 오른쪽으로 걸어도 몸은 왼쪽 위를 본다.
- 총구 반대쪽으로 걸을 때(뒷걸음질)도 같은 걷기를 재생한다. 서기와 뻗기를 번갈아 반복하는 방식이라 거꾸로 재생해도 똑같아 보이므로 따로 그리지 않는다.
- 무기는 방향별로 그리지 않는다. 무기 그림 1장을 조준 각도대로 돌리고, 위쪽을 볼 때는 몸 뒤에 그린다(`src/entities/Player.ts`의 `syncView`).
- 그래서 몸 그림에는 **총을 잡는 손을 그리지 않는다**. 손은 무기 그림 쪽에 넣는다. 둘 다 그리면 손이 겹쳐 보인다.
- 서 있기와 걷기(방향당 1장)는 실제 그림이 들어가 있다(`src/assets/files/player/`, 불러오기는 `src/assets/images.ts`).
- 파일 이름은 `player-<동작>-<방향>.png`이다. 동작은 `stand`(서 있기), `walk`(발 뻗기), `walk2`(반대 발, 옆 방향만), 방향은 `down`, `rightdown`, `right`, `rightup`, `up`. 이 폴더에 이름 규칙대로 넣으면 코드 수정 없이 불러온다.
- 옆 방향(`rightdown`, `right`, `rightup`)의 `walk2`가 없으면 `walk`를 반복한다. 넣으면 바로 번갈아 쓴다.
- 걷기 한 장을 보여 주는 시간은 `src/config/player.ts`의 `walkFrameMs`(130ms).
- 실제 그림은 2배로 제작되므로 화면에는 `src/config/view.ts`의 `artScale`(0.5)을 곱해서 그린다.

### 몬스터 방향
- 몬스터는 **움직이는 방향**을 본다. 공격·주문 중에는 **플레이어 쪽**을 본다.
- 방향이 경계에서 떨리지 않게, 한 번 바꾸면 0.15초 동안 유지한다(`src/config/view.ts`의 `facingHoldMs`). 그림에는 영향 없음.
- 방향 고르기는 이미 들어가 있다(`src/view/facing.ts`). 그림 이름은 `monster-<id>-<방향>`이고 방향은 `down`, `downRight`, `right`, `upRight`, `up`이다. 실제 에셋은 같은 이름으로 넣으면 된다.
- 지금 프로토타입은 방향마다 얼굴만 다르게 그린다. 앞쪽 방향은 눈(눈동자가 보는 쪽으로 쏠림)과 입, 위쪽 방향은 얼굴 대신 등 무늬.

몬스터의 실제 충돌 크기(발자국)는 `src/config/monsters.ts`의 `footprint`다. 그림의 발 부분 너비를 이 값의 2배에 맞추면 판정과 그림이 일치한다.

## 10. 파일 이름과 폴더

### 이름 규칙
소문자, 하이픈(`-`) 구분, 프레임 번호는 두 자리.

```
<대상>-<동작>-<방향>-<번호>.png
player-walk-se-01.png        # 플레이어, 걷기, 오른쪽 아래, 1번 프레임
grunt-attack-n-03.png        # 그런트, 공격, 위, 3번 프레임
fx-explosion-07.png          # 이펙트
sfx-pistol.ogg / sfx-pistol.mp3
bgm-title.ogg / bgm-title.m4a
```

방향 표기: `s`(아래) `se`(오른쪽 아래) `e`(오른쪽) `ne`(오른쪽 위) `n`(위). 왼쪽은 반전하므로 만들지 않는다.

### 폴더 구조 (게임에 들어가는 파일)
```
games/monster-wave/public/assets/
├── atlas/          characters.png + .json, world.png + .json, fx.png + .json, ui.png + .json
├── audio/
│   ├── sfx/        sfx.ogg + sfx.mp3 + sfx.json (오디오 스프라이트)
│   └── bgm/        bgm-title.ogg/.m4a, bgm-game-early.ogg/.m4a ...
├── fonts/          *.woff2
└── title-bg.jpg
```

개별 프레임 원본(`.psd`, 낱장 `.png`, `.wav`)은 게임에 넣지 않고 별도 폴더나 저장소에 보관한다.
지금은 받은 낱장 그림을 `src/assets/files/`에 두고 `src/assets/images.ts`에서 불러온다(빌드할 때 파일 이름에 해시가 붙는다). 그림이 늘어나면 위 구조처럼 아틀라스로 묶는다.

`public/` 아래 파일은 상대 경로(`assets/...`)로 불러온다 (`/assets/...`처럼 `/`로 시작하면 포털 안에서 404).

## 11. 지금 코드와의 대응

지금 텍스처 이름은 [`src/assets/keys.ts`](src/assets/keys.ts) 한곳에서 관리한다.
같은 이름으로 이미지를 불러오면 게임 코드는 대부분 그대로 동작한다.

| 지금 텍스처 이름 | 바꿀 에셋 | 코드 작업 |
| --- | --- | --- |
| `player-<동작>-<방향>` | 플레이어 5방향 그림 | 서 있기·걷기 적용됨. 맞음, 걸을 때 들썩임 추가 필요 |
| `gun` | 플레이어 무기 7종 | 현재 무기에 따라 그림 바꾸기 추가 필요 |
| `monster-<id>-<방향>` | 몬스터 시트 | 방향·동작별 애니메이션 재생 추가 필요 |
| `shadow` | 발밑 그림자 | 그대로 교체 |
| `floor` | 바닥 타일 | 여러 종 무작위 배치 추가 필요 |
| `wall` | 벽 윗면·앞면 | 모서리 조각 고르기(autotile) 추가 필요 |
| `barricade`, `barrel` | 설치물 | 바리케이드 손상 단계 전환 추가 필요 |
| `bullet`, `rocket`, `grenade`, `fireball` | 투사체 | 그대로 교체 (애니메이션은 추가) |
| `ammo-crate`, `health-pack` | 아이템 | 그대로 교체 |
| `particle`, `blast` | 이펙트 | 프레임 애니메이션으로 교체 |
| (없음) | 효과음 | `src/audio/Sfx.ts`의 합성음을 파일 재생으로 교체 |
| (없음) | BGM | 새로 추가 (곡 전환, 음소거 연동) |

에셋을 바꿀 때 텍스처 생성 코드(`src/assets/textures.ts`)는 지우지 말고, 해당 이미지가 없을 때 쓰는 대체 그림으로 남겨 두면 에셋을 조금씩 바꿔 넣을 수 있다.
