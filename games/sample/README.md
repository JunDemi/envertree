# 별 받기 (sample)

바구니를 좌우로 움직여 하늘에서 떨어지는 별을 받는 아케이드 게임.
별을 받을수록 별이 빨리, 자주 떨어지고, 3개를 놓치면 끝난다.

`games/_template`을 복사해서 만든 첫 번째 게임으로, 템플릿 사용법과 포털 연동(game-sdk)을 보여주는 예제 역할도 한다.

| 항목 | 값 |
| --- | --- |
| slug / 주소 | `sample` / `/games/sample` |
| 기본 해상도 | 800 × 600 (4:3) |
| 기술 | Phaser 4.2, Vite 8, TypeScript 7 |
| 물리 | Arcade Physics (중력 없음, 속도로만 이동) |
| 포털 등록 | `apps/portal/src/lib/games.ts`의 `slug: "sample"` 항목 |
| 썸네일 | `apps/portal/public/thumbnails/sample.svg` |

---

## 1. 플레이 방법

### 조작

| 입력 | 동작 | 사용하는 화면 |
| --- | --- | --- |
| `←` `→` 키 | 바구니 좌우 이동 (초당 600px) | 게임 |
| 마우스 이동 / 터치 드래그 | 바구니가 포인터의 x 위치로 즉시 이동 | 게임 |
| 클릭 / 탭 / `Space` | 시작, 다시 시작 | 시작 화면, 게임 오버 화면 |

### 규칙

- 별이 바구니에 닿으면 **+1점**.
- 별이 화면 아래로 빠지면 **목숨 -1**, 화면이 짧게 흔들린다.
- 목숨은 3개(`♥♥♥`). 0이 되면 게임 오버.
- 점수가 오를수록 **별이 떨어지는 속도**와 **새 별이 나오는 빈도**가 함께 올라간다. (→ 5. 난이도 곡선)

---

## 2. 화면 흐름

```
 ┌──────────────┐  클릭/Space   ┌──────────────┐  목숨 0   ┌────────────────┐
 │ StartScene   │ ────────────▶ │ GameScene    │ ───────▶ │ GameOverScene  │
 │ "start"      │               │ "game"       │  0.4초 뒤 │ "gameover"     │
 │ ready() 전송 │               │ gameStart()  │          │ gameOver() 전송│
 └──────────────┘               └──────────────┘          └────────────────┘
                                       ▲     클릭/Space (0.5초 뒤부터)  │
                                       └────────────────────────────────┘
```

- 다시 시작하면 시작 화면을 거치지 않고 바로 `GameScene`으로 간다.
  그래서 `ready()`는 페이지를 열었을 때 한 번만 전송된다.
- 씬이 바뀌면 Phaser가 이전 씬의 입력 리스너, 키보드 리스너, 타이머를 모두 정리한다.
  다시 시작해도 이벤트가 중복으로 걸리지 않는다. (Phaser 소스의 `InputPlugin`, `KeyboardPlugin`, `Clock`의 `shutdown`에서 확인)

## 3. 파일 구조

```
games/sample/
├── index.html              # <div id="game"> 하나. 화면 전체를 쓰도록 margin 0, overflow hidden
├── package.json            # name: "sample" (pnpm --filter sample ...)
├── vite.config.ts          # base: "./" (포털 /play/sample/ 아래에서 리소스 로드용)
├── tsconfig.json
├── public/assets/star.svg  # 별 이미지 (유일한 외부 리소스)
└── src/
    ├── config.ts           # GAME_WIDTH, GAME_HEIGHT, FONT_FAMILY
    ├── main.ts             # Phaser.Game 생성 (스케일, 물리, 씬 등록)
    └── scenes/
        ├── StartScene.ts   # 리소스 로드, 바구니 텍스처 생성, 타이틀 화면
        ├── GameScene.ts    # 실제 게임 로직
        └── GameOverScene.ts# 결과 화면, 점수 전송, 재시작
```

템플릿과 비교하면 `main.ts`(물리 추가, 배경색), `StartScene.ts`, `GameScene.ts`, `index.html`의 제목, `package.json`의 이름이 다르다.
`GameOverScene.ts`, `config.ts`, `vite.config.ts`는 템플릿 그대로다.

## 4. 구현 상세

### 4-1. 게임 설정 — `src/main.ts`

```ts
new Phaser.Game({
  type: Phaser.AUTO,                 // WebGL 우선, 안 되면 Canvas
  parent: "game",
  backgroundColor: "#0f172a",
  scale: {
    mode: Phaser.Scale.FIT,          // 4:3 비율을 유지하며 iframe에 맞춤 (남는 곳은 검은 여백)
    autoCenter: Phaser.Scale.CENTER_BOTH,
    width: 800, height: 600,
  },
  physics: { default: "arcade", arcade: { gravity: { x: 0, y: 0 } } },
  scene: [StartScene, GameScene, GameOverScene],  // 첫 번째가 먼저 실행
});
```

- 게임 안의 좌표는 항상 800×600 기준이다. 화면이 커지거나 작아져도 Phaser가 확대/축소만 하므로 게임 로직은 크기를 신경 쓰지 않는다.
- 중력을 0으로 두고 별에 일정한 아래 방향 속도를 준다. 그래서 별은 가속 없이 **등속**으로 떨어진다.

### 4-2. 시작 화면 — `StartScene.ts`

| 단계 | 내용 |
| --- | --- |
| `preload` | `assets/star.svg`를 48×48 크기 텍스처 `"star"`로 불러온다. 경로가 상대 경로라 포털의 `/play/sample/` 아래에서도 동작한다. |
| `create` ① | 바구니 텍스처 `"basket"`을 이미지 파일 없이 만든다. 120×24 하늘색(`#38bdf8`) 둥근 사각형을 그린 뒤 `generateTexture`로 저장한다. 텍스처는 게임 전체에서 공유되므로 `textures.exists`로 한 번만 만든다. |
| `create` ② | 큰 별(2배), 제목 "별 받기", 설명 두 줄, 깜빡이는 "클릭 또는 Space로 시작"(투명도 1 ↔ 0.3, 0.7초 왕복 반복)을 그린다. |
| `create` ③ | `ready()`로 포털에 로딩이 끝났다고 알린다. |
| `create` ④ | 클릭 또는 Space를 **한 번만**(`once`) 받아 `GameScene`으로 넘어간다. |

### 4-3. 게임 화면 — `GameScene.ts`

#### 상태

| 필드 | 초기값 | 설명 |
| --- | --- | --- |
| `score` | 0 | 받은 별 개수 |
| `lives` | 3 (`START_LIVES`) | 남은 목숨 |
| `over` | `false` | 게임 오버 처리 중인지. `true`면 `update`를 멈춘다. |
| `spawnTimer` | — | 다음 별 생성 예약. 게임 오버 때 취소한다. |

씬은 다시 시작할 때 재사용되므로 모든 상태를 생성자가 아니라 `create()`에서 초기화한다.

#### 화면 구성

| 오브젝트 | 위치 / 크기 | 비고 |
| --- | --- | --- |
| 점수 텍스트 | 왼쪽 위 (20, 16) | `점수: N`, 26px 흰색 |
| 목숨 텍스트 | 오른쪽 위 (780, 16), 오른쪽 정렬 | `♥`(남은 목숨) + `♡`(잃은 목숨) |
| 바구니 | 가운데 아래 (400, 560), 120×24 | 물리 몸체. `setImmovable`(별에 밀리지 않음), `setCollideWorldBounds`(화면 밖으로 못 나감) |
| 별 그룹 | — | `physics.add.group()`. 새 별은 이 그룹에 추가한다. |

#### 바구니 이동

- **키보드**: 매 프레임(`update`) `←`, `→`가 눌려 있는지 보고 x 방향 속도를 -600 / 0 / +600으로 정한다. 둘 다 누르면 0이 되어 멈춘다. 화면 끝에서 끝(680px)까지 약 1.1초 걸린다.
- **마우스·터치**: `pointermove`가 올 때마다 바구니의 x를 포인터 x로 바로 옮긴다. 바구니가 화면 밖으로 반쯤 나가지 않게 60~740으로 제한한다(바구니 폭의 절반 = 60).
- 마우스로 x를 직접 바꿔도 받기 판정은 정확하다. Arcade Physics가 매 물리 단계 시작 시 게임 오브젝트 위치에서 몸체 위치를 다시 읽기 때문이다(`Body.preUpdate` → `updateFromGameObject`).

#### 별 생성 — `spawnStar()`

```ts
x = 30 ~ 770 사이 무작위, y = -30 (화면 위 바깥)
낙하 속도   = 180 + score × 12   (px/초)
회전 속도   = -120 ~ 120 무작위   (도/초, 보기용)
다음 생성까지 = max(350, 900 − score × 20)  (ms)
```

- 게임을 시작하자마자 첫 별을 만들고, 별을 만들 때마다 **그 시점의 점수로** 다음 별을 예약한다(`time.delayedCall`).
  - Phaser 4에서는 `TimerEvent.delay`가 읽기 전용이라 반복 타이머의 간격을 바꿀 수 없다. 그래서 한 번짜리 타이머를 이어 붙이는 방식으로 만들었다.
- 낙하 속도는 별이 생길 때 정해지고, 떨어지는 도중에는 바뀌지 않는다.

#### 받기 판정

```ts
this.physics.add.overlap(this.basket, this.stars, (_basket, star) => {
  star.destroy();
  this.score += 1;
  this.scoreText.setText(`점수: ${this.score}`);
});
```

- 바구니와 별의 물리 몸체가 겹치는 순간 별을 없애고 점수를 올린다.
- Arcade Physics의 몸체는 회전하지 않는 사각형이다. 별 그림이 돌아가도 판정 영역은 48×48 사각형 그대로라서, 별 모양보다 판정이 조금 넉넉하다.

#### 놓침 판정

- 매 프레임 별 그룹을 돌면서 `y > 630`(화면 아래 + 30px)인 별을 없애고 `loseLife()`를 부른다.
- `getChildren()`은 목록의 복사본을 돌려주므로, 반복 중에 별을 지워도 다른 별을 빠뜨리지 않는다.
- 한 프레임에 여러 개를 놓쳐도 목숨이 0이 되는 순간 반복을 멈춘다. 게임 오버가 두 번 처리되지 않는다.

#### 목숨 감소와 게임 오버 — `loseLife()`

1. `lives`를 1 줄이고 하트 표시를 갱신한다.
2. 카메라를 150ms 동안 흔든다(강도 0.01).
3. 목숨이 0이면:
   - `over = true` → `update`가 더 이상 아무것도 하지 않는다.
   - `physics.pause()` → 화면의 별과 바구니가 그 자리에 멈춘다.
   - 예약된 다음 별을 취소한다.
   - 0.4초 뒤 `GameOverScene`으로 넘어가며 `{ score }`를 전달한다. 잠깐 멈춘 화면을 보여줘서 어디서 놓쳤는지 알 수 있게 한다.

### 4-4. 게임 오버 화면 — `GameOverScene.ts`

1. "게임 오버", `점수: N`(노란색), "클릭 또는 Space로 다시 시작"을 그린다.
2. `gameOver({ score })`로 포털에 최종 점수를 보낸다.
3. **0.5초 뒤부터** 클릭 또는 Space를 받는다. 게임 중에 누르던 입력 때문에 결과를 보기도 전에 바로 다시 시작되는 것을 막기 위해서다.
4. 입력이 들어오면 `GameScene`을 다시 시작한다.

## 5. 난이도 곡선

별은 y = -30에서 생겨 y = 630을 넘으면 놓친 것으로 처리된다. 끝까지 떨어지는 거리는 660px이다.

| 점수 | 낙하 속도 (px/초) | 화면을 지나는 시간 | 생성 간격 |
| --- | --- | --- | --- |
| 0 | 180 | 약 3.7초 | 0.90초 |
| 5 | 240 | 약 2.8초 | 0.80초 |
| 10 | 300 | 약 2.2초 | 0.70초 |
| 20 | 420 | 약 1.6초 | 0.50초 |
| 28 | 516 | 약 1.3초 | **0.35초 (최소값 도달)** |
| 40 | 660 | 약 1.0초 | 0.35초 |
| 50 | 780 | 약 0.85초 | 0.35초 |

- 생성 간격은 점수 28부터 0.35초로 고정된다.
- 낙하 속도는 **상한이 없다.** 점수가 높아질수록 계속 빨라져서 결국 받을 수 없게 되고, 이것이 사실상 게임의 끝이다.

## 6. 포털 연동

`@envertree/game-sdk`의 세 함수를 부른다. 메시지 형식과 포털 쪽 검증은 루트 [README의 메시지 규약](../../README.md#메시지-규약) 참고.

| 호출 위치 | SDK 함수 | 보내는 시점 | 포털 화면 변화 |
| --- | --- | --- | --- |
| `StartScene.create` | `ready()` | 별 이미지 로드가 끝나고 시작 화면이 그려진 직후 | 상태 "준비 완료" (파란 점) |
| `GameScene.create` | `gameStart()` | 한 판 시작할 때마다 (다시 시작 포함) | 상태 "플레이 중" (초록 점) |
| `GameOverScene.create` | `gameOver({ score })` | 결과 화면이 뜰 때 | 상태 "게임 오버" (빨간 점), 이번 점수와 최고 점수 표시 |

- 포털이 보여주는 "최고 점수"는 **그 페이지를 보고 있는 동안만** 유지된다. 새로고침하면 사라진다(아직 저장 기능 없음).
- 포털 밖에서 단독 실행하면(`pnpm --filter sample dev`) 부모 창이 없으므로 메시지를 보내지 않고 브라우저 콘솔에 `[game-sdk] 포털 밖에서 실행 중 — 전송 생략`만 남긴다.
- 키보드 입력은 게임 iframe에 포커스가 있어야 들어간다. 포털은 iframe이 로드되면 자동으로 포커스를 주고, 게임 화면을 클릭해도 포커스가 간다.

## 10. 알려진 한계와 개선 아이디어

샘플이라 일부러 단순하게 만들었다. 실제 게임으로 키운다면 다음을 고려할 만하다.

- **낙하 속도 상한 없음**: 점수 40 전후부터 사실상 받을 수 없다. 상한을 두거나 다른 방식으로 난이도를 올리는 게 좋다.
- **판정이 사각형**: 회전하는 별 모양과 판정 영역(48×48 사각형)이 정확히 일치하지 않는다. 원형 판정(`body.setCircle`)으로 바꿀 수 있다.
- **입력 전환**: 마우스를 움직이면 키보드로 옮긴 위치를 덮어쓴다. 보통 한 가지만 쓰므로 문제는 적다.
- **일시정지, 사운드, 효과 없음**: 별을 받을 때 효과음이나 파티클을 넣으면 손맛이 좋아진다.
- **최고 점수 저장 없음**: 포털의 점수 DB와 랭킹(이번 범위 밖)이 생기면 `gameOver`로 보낸 점수를 그대로 쓸 수 있다.
- **점수 위조 가능**: 점수는 브라우저에서 계산해 보낸다. 랭킹을 만들 때는 서버 쪽 검증(비정상적으로 높은 점수 차단 등)이 필요하다.
